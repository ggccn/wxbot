# 微信防封策略

> 这份文档回答一个问题：**怎么让这个号尽量不被封**。不是保证，是把这个号的
> 「可疑程度」压到和普通用户差不多的水平。

## 一、先搞清楚微信在看什么

微信从不公布封号规则，但从公开的实测总结和开发者反馈看，判定信号大致是这几类
（参考：[腾讯云社区：微信封号机制其实是个"行为协议"](https://cloud.tencent.com.cn/developer/article/2521031)、
[实测 30 天的风控铁律](https://baijiahao.baidu.com/s?id=1870248321275601800)、
[微信个人账号使用规范](https://westore.weixin.com/cgi-bin/readtemplate?t=page/agreement/personal_account&lang=zh_CN)）：

| 信号 | 具体表现 | 我们怎么规避 |
| --- | --- | --- |
| 消息频率与重复率 | 短时间连发、同样的话反复发、结构高度雷同 | 每人/全号每日硬上限；同一句话 30 分钟内最多 2 次；回复前随机延迟 |
| 群操作 | 频繁拉人、建群、退群、群发 | 不拉人、不建群、群聊只在被 @ 时回 |
| 加好友行为 | 批量加人、加陌生人 | 完全不主动加人 |
| 登录/环境 | 设备频繁切换、异地登录、多开 | 只在这台机器登录，不双开，不换 IP |
| 行为轨迹 | 每次点同一个像素、光标瞬移、匀速打字 | 用带拟人节奏层的库（随机落点、贝塞尔轨迹、抖动间隔） |
| 内容违规 | 广告、外链、二维码、涉赌涉黄涉贷 | 发送前的关键词/正则审查，命中就换成婉拒 |
| 被投诉 | 骚扰陌生人被举报，风险等级大幅上升 | 只回白名单里的人（陌生人一律不理） |
| 支付异常 | 新号立即大额转账/收款 | 机器人不做任何支付相关的事 |

另外，**第三方外挂/多开/自动群发工具是封号概率最高的行为**，一旦被关联到就
是 7–90 天功能限制起步。我们这条路刻意不碰它们：

- 不注入微信进程（WeChatFerry/驱动注入那条路已经放弃，且微信 3.9 已被腾讯禁登）；
- 不改协议、不伪装客户端，消息走的是**官方客户端自己的发送通道**；
- 读消息读的是**本机数据库文件**，不产生任何网络请求。

代价是发送要占用鼠标键盘（因此锁屏时发不出去），换来的是账号侧几乎没有
「非官方客户端」的特征。

## 二、四层防线

### 第 1 层：账号本身（需要你配合，效果最大）

- [ ] 小号**完成实名认证**并绑定本人银行卡；
- [ ] 小号在手机上**正常使用一段时间**（聊天、看朋友圈、偶尔小额支付），不要
      注册当天就交给机器人；
- [ ] 用小号的手机端常驻登录，桌面端也一直登录，**不要反复扫码/切换设备**；
- [ ] 不要在这个号上装任何「微信多开」「自动抢红包」「群发助手」类工具；
- [ ] 不要给这个号改头像/昵称/签名等资料（新号频繁改资料也算异常）。

### 第 2 层：行为（代码已实现，见 `safety.py`）

| 措施 | 默认值 | 说明 |
| --- | --- | --- |
| 只回好友 | `allow_friends = true` | 白名单里的人是永久放行；名单外**只有本号好友**会回，陌生人（非好友）一律不理，避免「骚扰」投诉 |
| 永不主动发 | — | 除了回复和主人的命令，机器人不会主动发任何消息 |
| 回复延迟 | 3–9 秒 + 每字 0.045 秒 | 模拟「看消息 + 打字」，长回复最多等 18 秒 |
| 每人每日上限 | 80 条（新手期 30） | 一个人一天聊不了 80 条，超了就不回 |
| 全号每日上限 | 300 条（新手期 60） | 新号头 14 天按 60 条走 |
| 分钟/小时限流 | 6 条/分钟、60 条/小时（全局 30 条/分钟） | 防止一次性刷屏 |
| 免打扰 | 23:30–08:00 | 深夜自动闭嘴（主人在此期间发命令仍可执行） |
| 拟人节奏层 | `WECHATAUTO_RHYTHM=calm` | 库内置：两次发送间隔 6–14 秒、5 分钟内最多 3 次写动作、光标走曲线 |

### 第 3 层：内容（代码已实现）

发送前逐条检查，命中任何一条就改发一句婉拒：

- 任何 URL / 链接（`http://`、`www.`、`t.cn`、公众号链接）
- 11 位手机号
- 高危词：转账、红包、收款码、银行卡、身份证、验证码、贷款、刷单、兼职日结、
  博彩、赌博、加好友、加微信、群发、二维码、扫一扫、下载 APP、代理、返利……
- 同一会话 30 分钟内重复同一句话超过 2 次

### 第 4 层：监控与熔断（代码已实现）

- 连续 3 次发送失败 → 立即熔断，停手 30 分钟并写日志；
- 微信掉线（读不到账号信息）→ 进程退出码 2，由计划任务延迟重拉；
- 熔断状态、每日额度都落盘在 `data/safety.json`，重启不清零；
- 发 `/safety` 可以随时查看「今日已发多少条、白名单几人、是否熔断」。

## 三、你必须知道的红线

1. **别用小号去主动加人、拉群、群发**。机器人只回不说话，你手动做这些事才是
   真正的风险来源。
2. **别让朋友把机器人拉进陌生的群**。群聊目前是关闭的（`allow_groups = []`），
   要开的话先想清楚那个群里有没有会投诉的人。
3. **别让它替你发广告、发文件、发链接**。内容审查会拦，但拦不住你手动发。
4. **同一个号不要同时跑两个自动化程序**。两个进程抢鼠标键盘，行为会非常怪。
5. **锁屏时它发不出消息**（GUI 自动化点不到窗口）。要长时间挂机就把电源设置里的
   睡眠关掉、屏幕可以不关。

## 四、万一被限制了怎么办

| 现象 | 大概率原因 | 处理 |
| --- | --- | --- |
| 发消息提示「操作过于频繁」 | 触发了频率限制 | 停 24 小时，别重试；把 `daily_total` 再调低 |
| 要求重新登录 | 环境/行为异常（库里作者 2026-09 就遇到过一次） | 扫码重新登录，停一天再开 |
| 功能限制（不能加好友/发朋友圈） | 被举报或高频操作 | 停用机器人 3–7 天，正常手动使用 |
| 限制登录/封禁 | 累积风险 | 走官方申诉；这个号不要再接自动化 |

## 五、为什么选这条路

| 方案 | 封号风险 | 能力 | 结论 |
| --- | --- | --- | --- |
| WeChatFerry / 驱动注入 | 高（且微信 3.9 已被禁登） | 全功能 | 已放弃 |
| hook 协议 / 逆向 API | 很高 | 全功能 | 不碰 |
| **UI 自动化 + 本地库读消息（本方案）** | **低–中** | 收发文本、读历史 | 采用 |
| 企业微信 / 公众号 | 极低 | 不能进个人好友/群 | 不满足需求 |

本方案的残余风险主要来自**行为本身**（一个号长期秒回、深夜也回、回复风格机械），
所以上面的延迟、静默时段、白名单、每日额度不是可选项，是这套东西能长期跑下去的
前提。要调松，先想清楚拿什么换。
